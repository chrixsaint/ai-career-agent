### Version 1 Artifact Specification: `generate-tests.prompt.specification.md`

#### 1. Purpose
#### VERIFIED FACT
This prompt standardizes **Step 7 (Verification)** of the project's 11-step engineering lifecycle. It ensures that automated tests generated by AI are independent, deterministic, and follow the project's established testing standards, specifically utilizing `pytest` and `AsyncClient` for FastAPI components.

#### 2. Scope
#### VERIFIED FACT
This specification governs the physical prompt file located at `.github/prompts/generate-tests.prompt.md` and its governing engineering specification in `docs/specifications/prompts/`. It applies to the generation of unit and integration tests for new or modified source code.

#### 3. Dependencies
#### VERIFIED FACT
*   **`docs/AI_DEVELOPMENT_WORKFLOW.md`**: Provides the engineering lifecycle stage (Step 7) this prompt implements.
*   **`docs/COPILOT_CONFIGURATION.md`**: Establishes the classification of the prompt as a **Required** configuration.
*   **`docs/PROMPT_LIBRARY.md`**: Defines the design principles (Single Responsibility) and standard structure.
*   **`docs/CODING_STANDARDS.md`**: Provides the authoritative criteria for test quality, including the requirement for `AsyncClient` and coverage of failure scenarios.

#### 4. Inputs
#### VERIFIED FACT
The prompt requires the following data to generate valid, high-quality tests:
*   **Target Source Code**: The code for which tests are being generated.
*   **Approved Implementation Plan**: The approved Step 5 implementation strategy for the current implementation package.
*   **Functional Requirements**: Relevant entries from `REQUIREMENTS.md` to ensure coverage of business logic.
*   **Current Repository State**: To ensure tests are grounded in implemented truth and utilize existing fixtures or mocks.
*   **Technical Context**: Reference to governing architecture or coding standards.

#### 5. Outputs
#### VERIFIED FACT
The prompt must produce executable Python test code that:
*   Utilizes the **`pytest`** framework.
*   Employs **`AsyncClient`** for all FastAPI-related tests.
*   Validates request handling, response models, and HTTP status codes.
*   Covers both **successful and failure scenarios**.
*   Adheres to the **Single Responsibility Principle** for test modules.
*   Maintains traceability between generated tests and the applicable functional requirements.

#### 6. Relationship to Repository Instructions
#### VERIFIED FACT
While repository instructions provide persistent grounding (the "Who" and "What"), this prompt provides **reusable tactical logic** (the "How") for the verification phase.

#### 7. Relationship to AI Development Workflow
#### VERIFIED FACT
This artifact is the operational implementation of **Step 7 (Verification)** of the frozen development lifecycle.

#### 8. Position within the 11-step engineering lifecycle
#### VERIFIED FACT
The prompt is triggered at **Step 7** to generate the automated verification suite required before a task can be considered "Done".

#### 9. Required Prompt Inputs
#### VERIFIED FACT
Using official GitHub prompt file syntax, the prompt shall utilize:
*   `${input:code}`: The source code to be tested.
*   `${input:plan}`: The approved implementation strategy from Step 5.
*   `${input:requirements}`: The functional requirements the code must satisfy.
*   `${input:context}`: Reference to governing architecture, existing fixtures, or current repository state.

#### 10. Expected Prompt Output
#### ENGINEERING RECOMMENDATION
The output should be formatted as **executable Python code** preceded by a brief **Test Coverage Summary**.
*   **Rationale**: Providing a summary allows for rapid human review of the "test plan" before the code is accepted or executed.

#### 11. Prompt Constraints
#### VERIFIED FACT
The generated tests must NOT:
*   Introduce new, unauthorized testing libraries.
*   Hardcode secrets, tokens, or personal information.
*   Modify existing production source code.
*   Bypass the requirement for independent and deterministic execution.

#### 12. Human Approval Gates
#### VERIFIED FACT
The output of this prompt is **advisory**. The Human Developer must review the generated tests for correctness and maintainability before they are merged into the repository.

#### 13. Verification Requirements
#### VERIFIED FACT
The prompt must instruct the agent to define verification commands and rely on **observable execution results**, including `pytest`, `ruff check .`, and `ruff format .`, to validate the generated test suite.

#### 14. Definition of Done
#### VERIFIED FACT
A test generation task is complete when the generated suite satisfies the project's coding standards, covers all relevant requirements, defines the required verification commands, and is ready for mandatory Human Developer review.

#### 15. Repository Boundaries
#### VERIFIED FACT
The prompt must focus exclusively on testing the **current implementation package** and must not attempt to refactor unrelated modules.

#### 16. Prompt Lifecycle
#### VERIFIED FACT
This artifact is currently in the **Planned** stage of the **Repository Truth Policy**.
