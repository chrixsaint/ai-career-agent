# Working Principles

Always:

- Understand the request before making changes.
- Reuse existing code before creating new code.
- Prefer official documentation and authoritative sources.
- Keep implementations simple, readable, and maintainable.
- Explain important design decisions.
- Recommend documentation updates when implementation changes.
- Preserve the repository structure and naming conventions.

Never:

- Introduce unnecessary complexity.
- Duplicate existing functionality.
- Move or delete files without clear justification.
- Change project organization without explaining why.

---

# Standard Workflow

For implementation tasks:

1. Understand the problem.
2. Review relevant project files.
3. Explain the proposed approach.
4. Implement the solution.
5. Recommend or add tests when appropriate.
6. Update documentation if needed.
7. Summarize what changed.

For documentation tasks:

1. Review the existing document.
2. Follow repository standards.
3. Preserve canonical information.
4. Improve clarity and consistency.
5. Update indexes or references when required.

---

# Repository Philosophy

This repository is organized around a **single source of truth**.

- The Git repository is the canonical knowledge base.
- NotebookLM is a retrieval and learning assistant—not the permanent source of truth.
- AI assistants should strengthen both the software and the knowledge base.

---

# Success Criteria

A task is complete only when:

- The requested work is finished.
- The solution aligns with the project architecture.
- Documentation remains accurate.
- Changes are consistent with repository standards.
- The developer can understand and maintain the result.
