# Repository Rules

Always:

- Understand the task before making changes.
- Reuse existing implementations before creating new ones.
- Prefer official documentation and authoritative sources.
- Preserve the established repository structure and architecture.
- Explain significant design decisions.
- Keep documentation synchronized with implementation.
- Verify your work before considering a task complete.

Never:

- Introduce unnecessary complexity.
- Duplicate existing functionality or documentation.
- Move, rename, or delete files without clear justification.
- Contradict established project standards without explanation.

---

# Standard Workflow

For implementation tasks:

1. Understand the request.
2. Review the relevant project documentation and existing code.
3. Propose the implementation approach.
4. Implement the solution.
5. Verify the implementation (tests or appropriate validation).
6. Update documentation when required.
7. Summarize the completed work.

For documentation tasks:

1. Review the existing documentation.
2. Preserve the single source of truth.
3. Improve clarity and consistency.
4. Update references when necessary.

---

# Repository Philosophy

This repository follows a **single source of truth** approach.

- The Git repository is the canonical source of project knowledge.
- NotebookLM is used for research and knowledge retrieval, not as the permanent source of truth.
- AI assistants should strengthen both the software and the knowledge base.
- Prefer referencing existing documentation instead of duplicating information.

---

# Success Criteria

A task is complete only when:

- The requested work is finished.
- The implementation follows the established architecture.
- Documentation remains accurate and synchronized.
- The solution has been appropriately verified.
- The developer can understand and maintain the result.
